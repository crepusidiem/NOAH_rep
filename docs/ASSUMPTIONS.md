## Classification and resolution policy

**EXPLICIT** means the choice is directly in the paper. **DERIVED** means it follows without adding discretion. **ASSUMED** means an unresolved detail is filled by a clearly labeled candidate. **DEVIATION** means an alternative changes a stated mechanism, target, or information set.

Author-specific resolution of the A-IDs below remains OPEN; the architecture audit records concrete candidates selected within the authorized implementation scope. Candidate choices in existing code require evidence and resolution under this register. See [IMPLEMENTATION_GUIDE.md](IMPLEMENTATION_GUIDE.md) for the current code snapshot and verified upstream encoder details. “Unspecified” is not permission to adopt a library default invisibly. Each named key must be independently configurable and included in the run manifest. Choices whose evidence is unresolved must not have a silent default in a paper-scale configuration.

Resolve by (1) author code or clarification tied to this paper version, (2) documented derivation, or (3) explicit assumption with sensitivity results. Scientific uncertainty is preserved even after a practical candidate is chosen.

For A-09, distinguish details absent from NOAH from details discoverable in upstream model releases. The 2026-10-14 guide verifies BioLORD pooling/length, RAD-DINO processor settings, OTIS interface/default-patch differences and EchoPrime normalization/frame/output interfaces. Those reduce practical uncertainty without proving the exact NOAH checkpoint or transforming upstream defaults into paper-explicit settings.

Literal paper-description and strict causal experiments are separate configurations. A single “faithful” switch is inadequate: timestamp alignment, prefix snapshot, aggregation availability, loss normalization, and clock bootstrapping can vary independently.

For the active15,000-patient M2 engineering dataset, [OPEN_SCIENTIFIC_ISSUES.md](OPEN_SCIENTIFIC_ISSUES.md) consolidates only unresolved material exceptions and PI questions. This register remains authoritative. Documented candidate choices can support occurrence-time data preparation while strict prospective or paper-exact claims remain unavailable; unrelated open questions do not create a blanket stop. A change that invalidates event identity, chronology or generated features stops only the affected output. Bulk compute still requires a separately approved bounded proposal.

The active C2 recipe is the reviewable [effective configuration](../configs/m2_c2.json), version `m2-c2-candidate-v1`. Its scientific fields are hash-locked to the matching implementation; edits require a new explicit implementation revision. It freezes conservative source/action mappings, exact longitudinal/encounter attribution, source clocks/precision, lexical equal-time ordering, native-unit finite numeric values and unit-suffixed specifics text,11 supported ICU vital item IDs and2h/1h extrema aggregation with contributor-mean time. Unknown/imprecise/unsupported records remain source-bound deferrals. Exact recipe details are not author settings. GPU queues select the existing128-token BioLORD, RAD-DINO CLS, OTIS upstream-linear and ECHO candidate recipes with pinned checkpoints; no cohort-scale embeddings are claimed before separate GPU execution. Full-trajectory pretraining eligibility must not determine an earlier clinical landmark risk set. SCI-02/03/08/19/20 record the remaining interpretation and selection questions.
