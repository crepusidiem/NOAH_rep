## Scientific contracts and unresolved approvals

Evaluation mode and experiment scale are separate axes. `paper_reproduction` preserves declared literal-paper information conventions and conservative retrieval interpretation; `strict_prospective` requires source-observed availability and cutoff-safe metadata/gaps. `reduced_pilot` is a scale/scope profile and must explicitly select an evaluation mode. It does not inherit prospective validity. The three generic JSON profiles remain disabled templates. The later researcher-approved named M1 integration is operational through `configs/m1.json` and the CPU-bounded `m1` command; its occurrence-time scope does not activate paper-exact or prospective profiles.

Every new event must retain source version/table/row, subject and encounter IDs, occurrence and available-at timestamps plus provenance/unknown status, units/content recipe and transformation revision. Views bind event ordering, cutoffs, demographic snapshot, gap policy and target ownership. Checkpoints bind architecture, full effective configuration, optimizer/schedule/RNG state, source/data/split manifests and code revision. Evaluation manifests require encounter/landmark/labels/horizons/censoring, allowed information, probe protocol, predictions, metrics and executed checks. Existing release gates remain mandatory; no legacy metric can be relabeled prospective.

The subsequent explicit M1 authorization and `configs/m1.json` resolve the following choices for this pilot only: M01 index/risk set and fixed landmarks; M02 source availability/unknown policy; M03 cutoff next-gap treatment; M04 demographic snapshots; M05 chosen endpoint/boundaries; M06 only if readmission is included; M08 loss normalization; M10 probe splits/seeds; the numeric and reduced-modality pilot declaration. M07 NEWS2, M11 exact encoder/architecture evidence and M12 MC are later dependencies. M09 alpha scope stays pending until the final milestone. The readmission audit is evidence against a lower-bound-only repair, not approval of episode merging or a complete-follow-up negative label.

## Dependency-ordered milestones

1. **B0: isolated initialization.** Preserve legacy bytes/history; verify checkpoint copies; migrate bounded candidates; pass clean-tree math, information-boundary and source/cache isolation checks. No clinical result is claimed.
2. **M1: small real-data end-to-end pipeline.** After the applicable approvals, use a small patient-disjoint versioned cohort and a declared category/numeric scope, retaining source/encounter/time/availability provenance. If text specifics are omitted, declare the scope deviation; never substitute zero embeddings. Run bounded reproducible training operations, save/reload a new revision, extract one approved landmark per index and fit/evaluate the approved clinical probe. Mortality/LOS can be considered before readmission follow-up and NEWS2 are resolved. B0 did not authorize that run; the later explicit M1 request did. The bounded run is now executed, with evidence in the M1 report.
3. **M2: scalable multimodal data and encoder integration.** The researcher-approved scope combines expanded cohort and all six modalities. M2-A: deterministic ≥10,000 assigned training patients plus disjoint validation/test and source inventory. M2-B: actual-source preprocessing/encoder checks, pinned assets and content-addressed caches, per-modality VERIFIED/PARTIALLY VERIFIED/BLOCKED status. M2-C: canonical provenance-preserving event shards, cache associations and shifted-target/window integrity, followed by explicit token eligibility counts. M2-D: category/modality/patient supports, rare-category and +24h endpoint readiness, tested cluster/paired inference and measured resource proposal. M2-A and inexpensive B are executed; the later integration report adds a208-event/7-patient/10-window genuine six-modality C smoke. Cohort-wide C and final D remain pending. The prepared source-index job is resource-approval gated; assigned patients do not certify model-ready qualification. No bulk encoding or training approval is implied. Never overwrite historical caches or require an all-modality intersection.
4. **M3: production-scale coverage acceptance after M2.** Close any remaining paper-category, cohort and extraction conformance gaps identified by actual M2-C/D evidence. The revised M2 owns initial six-modality integration; this later milestone is not a second specification. Keep dataset-version deviations explicit.
5. **M4: architecture/objective/training consistency.** Resolve or bound parameter mismatch and loss reductions, optimizer routing/clocks and exact resume; freeze a new architecture/configuration family. Do not pad parameter counts or transplant old tensors silently.
6. **M5: full paper evaluation and distinct prospective validation.** Execute literal landmark retrieval, reconstruction, free/oracle rollout, zero-shot MC and validated NEWS2 separately. Strict prospective reporting requires additional availability and future-invariance evidence, not merely a causal mask.
7. **M6: controlled alpha sweep.** Approve M09 and comparison estimand; freeze architecture/data/labels/probe/seed/checkpoint selection, explicitly pass alpha0, replay predictions and pass release gates. Separate resource/run approval required; HOLD.
