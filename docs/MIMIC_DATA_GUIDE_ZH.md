# MIMIC 与 NOAH 数据处理：入门讲解

2026-10-13。结合 NOAH 论文和当前仓库 main 提交 30dd669。本说明讲解数据与现有代码，不运行服务器任务、不修改数据管线或模型。

## 1. MIMIC 是怎样的数据集

MIMIC 收集去识别后的临床记录。一次住院会留下很多不同记录：何时入院、去了哪个科室、抽了什么血、结果是多少、用了什么药、医生写了什么、做了哪些影像或心电图。数据通常按业务系统分表或分文件存储。

可以把它想成医院的多本登记册。patients 记录患者信息，admissions 记录住院，labevents 记录化验，prescriptions/emar 等记录不同含义的药物信息。它们通过 ID 关联，不能把一个文件当作一个患者的完整病历。

MIMIC-IV 的 hosp 是医院范围的记录，icu 是 ICU 系统记录。ED 表示急诊，Note 是自由文本记录，CXR 是胸片，ECG 是心电图，ECHO 是超声心动图。某个模块有数据，不保证同一患者在其他模块也有数据。[官方 MIMIC-IV 2.2 说明](https://physionet.org/content/mimiciv/2.2/)

| 常见 ID | 它表示什么 | 连接时需要注意 |
|---|---|---|
| subject_id | 患者 | 同一患者的多次就诊可以串起来 |
| hadm_id | 一次住院 | 一位患者可能有多个；院外事件可能没有 |
| stay_id | 某个模块中的一次停留 | ICU 与 ED 的 ID 含义和命名空间要分开 |
| study_id | 一次检查/研究编号 | ECG、CXR、ECHO 不能仅凭相同数字跨模态连接 |
| itemid | 某个测量或临床项目的编号 | 需结合相应字典解释名称、单位和含义 |

MIMIC 的时间已经去识别。同一患者内时间间隔保留，但不同患者的去识别日历年份不能直接当作同一真实年份。anchor_year 与 anchor_age 可用于年龄代理，不能还原真实 DOB；超过 89 岁人群的 anchor_age 被设置为 91。[官方时间与年龄说明](https://physionet.org/content/mimiciv/2.2/)

## 2. “数据源”与“模态”有什么区别

数据源回答“数据来自哪套库/系统”，模态回答“这个事件的内容是什么形式”。因此六个来源并不与六个模态一一对应。

| NOAH 模态 | 你可以怎样理解 | 原始内容示例 | 论文怎样表示内容 |
|---|---|---|---|
| 分类 Categorical | 一个临床/行政状态或动作 | 入院、转科、给药开始 | 事件类别有可训练表示；可附文本类型细节 |
| 数值 Numeric | 一个有临床含义和单位的数 | 心率、血压、某个化验结果 | Fourier 数值表示，再投影；不是一句描述性文本 |
| 文本 Text | 连续的临床文字 | 出院小结、放射报告 | 冻结 BioLORD，768 维内容表示 |
| 胸片 CXR | 静态影像 | JPG 胸片像素 | 冻结 RAD-DINO，768 维内容表示 |
| 心电图 ECG | 电信号随时间变化 | 多导联电压波形 | 冻结 OTIS，192 维内容表示 |
| 超声 ECHO | 心脏运动的视频 | 超声视频帧 | 冻结 EchoPrime，512 维内容表示 |

这里的“维度”是向量里有多少个数。它不等于图片像素数、心电导联数或疾病类别数。embedding 可理解为编码器从原始内容提取的一组数字特征，不代表已经完成诊断，也不能保证能从向量还原原始内容。

结构化关系表常同时产生分类与数值事件；文本来源可以产生文本值或类型细节。药物开始是事件类别，药物名称是类型细节，剂量可能另带数值。**事件类别说明发生了什么，模态说明内容以什么形式表达。**

## 3. NOAH 为什么需要整理这些数据

原始表按医院业务保存，NOAH 则需要按患者、按时间保存。整理过程会改变组织方式，并对类型、单位、时间和缺失作出明确约定。

下面完全是虚构的教学例子：

| 时间 | 原始信息 | 统一事件 |
|---|---|---|
| 09:00 | admission 表中的入院行 | 分类事件：进入住院；类型细节：入院类型 |
| 09:15 | 心率 82，单位 bpm | 数值事件：生命体征；类型细节：心率；值：82 |
| 10:00 | ECG 清单中的路径 | ECG 事件；读取对应波形，由 OTIS 产生内容表示 |
| 11:00 | CXR metadata 中的检查与图像 ID | 胸片事件；读取对应像素，由 RAD-DINO 产生内容表示 |
| 12:00 | 医生/影像文本报告 | 文本事件；由 BioLORD 产生内容表示 |

以上事件合成一个有顺序的患者序列。另一个患者有自己的序列。模型输入同时告诉它：事件类型、类型细节、内容表示、发生时间，以及与前后事件之间的 gap。

持续事件需要区分开始与结束。例如 09:00 开始给药、11:00 停止，结束 token 应放在 11:00。不能在 09:00 的输入里提前加入“持续了两小时”，否则预测未来时已经看到了未来。

## 4. 清洗与整理的实际顺序

### 4.1 先确认能读到什么

路径存在、文件齐全、文件能解码、使用者有权限、训练样本已产出，分别对应不同检查。ECG 有 record_list.csv，只能说明有索引；要进一步读 .hea/.dat，才知道信号能否加载。CXR 有 metadata 也不等于图像文件完整。

报告、代码和文件都是证据，只是能支持不同结论。代码能证明处理规则存在，运行输出能证明某次执行完成；缓存文件和校验可以进一步证明产物可重复使用。

### 4.2 关联患者与临床项目

以 subject_id 连接各库，保留 hadm_id、检查 ID 和来源行。化验项目不能只变成一个无解释的 item 编号，还需要关联项目字典，使“肌酐”等临床语义与单位可追溯。连接前后应核对数量，防止一对多连接把同一事件复制多次。

### 4.3 解释数值、单位与缺失

相同项目可能有不同单位；换算必须有规则。真实 0、空值、不能转为 float 的文本，语义不同。不能统一填零，也不能把所有非数值化验文本都当垃圾。例如“阴性”可能是有用的结果，需要明确归入哪种事件/内容表示。

目前 lab 提取代码只保留可解析的 valuenum，并用 item_编号 作为 specifics，没有接入化验名称/单位字典。这是已实现的部分范围，尚不等于完整化验语义处理。

### 4.4 排序与时间特征

先规定事件时间和可获得时间。charttime 可理解为记录的临床时间；storetime 是记录进入系统的时间，其具体含义要按来源核对。两者可能不同。

当前代码采用小时作为 gap 单位，近似年龄采用年，同刻事件按类别/来源 ID 排序。它们是明确的代码选择，不意味着论文已指定这些细节。

只有最后一条记录不代表“下一条恰好同时发生”。下一 gap 不知道时应与真实 gap=0 区分。当前代码将最后 delta_next 设置为 0，这需要在训练时另行解决未知尾部标签与 loss mask。

### 4.5 降低高频生命体征的重复量

ICU 会高频记录心率等数值。若每条都直接作为 token，模型输入可能主要被重复测量占满。论文用滑窗 min/max 代表这一段，并放在窗口均值时间。

例：同一段心率为 80、82、100，min=80、max=100，可保留波动范围。窗口最大值可能来自后半段，所以预测窗口中间时需要检查数据是否已经可获得。

当前 helper 的默认跨度为 2 h、步长为 1 h；这些是本实现的假设。该函数还没有在现有两患者提取入口中被调用。论文没有给出这两个具体数字，也不能与 NEWS2 标签使用的 1 h 窗口混为一谈。

### 4.6 分模态读取与编码

| 内容 | 先做哪些事 | 与编码器的关系 |
|---|---|---|
| 文本 | 保留正文和时间，制定长文本处理、空文本规则 | BioLORD 冻结，输出 768 维；不能只保留 note ID |
| CXR | 关联患者/检查/图像，验证解码，确认图像处理版本 | RAD-DINO 使用像素；分类标签或 metadata 不能替代像素 |
| ECG | 检查 .hea/.dat 配对、导联、采样率、长度、异常值 | OTIS 使用波形；机器测量 CSV 不是同一种内容输入 |
| ECHO | 读取视频、区域裁剪与遮挡处理、帧采样和归一化 | EchoPrime 使用视频；只有超声测量数值表不满足视频路径 |
| 数值 | 保留项目、单位和存在性，使用一致的 Fourier 基 | 不需要下载一个外部编码器；相位和缩放仍需登记 |

ECG 官方说明每条 WFDB 记录包含 .hea 和 .dat，并提醒设备时钟可能与其他记录存在偏差。院外 ECG 不落在住院区间也可能是合理记录，不能一律删除。[ECG 1.0 官方说明](https://physionet.org/content/mimic-iv-ecg/1.0/)

“冻结”表示不在 NOAH 训练中更新这些外部编码器的参数；“离线预计算”表示先运行编码器、把向量缓存，训练时直接读取。编码器的精确权重和预处理必须记录，换一个同名模型版本不保证得到同一向量。

### 4.7 构造模型窗口

患者序列可能很长，训练中按论文使用 2048-token 窗口、256 overlap，并加六项人口学前缀。重叠区给后一个窗口提供上下文，但对应临床目标不能再次计入损失。

例如一个事件已在前窗训练，后窗再次看到它是为了理解后续事件。attention mask 决定模型可看哪些位置；loss mask 决定哪些目标贡献训练误差。这两个 mask 不能混为一谈。

70/15/15 划分在患者层面进行。同一个人的不同住院不能分别落入训练和测试，否则模型可能已认识测试患者。当前清单的 700/150/150 是这个比例的实际文件证据，但尚未验证全部事件路径及样本产物。

更准确的阶段描述是：**已经建立 pilot 患者清单和部分事件处理代码，接下来需要补足事件内容、实际读取与运行验收，再形成可训练样本。**

当前 CXR 路径指向 mimic-cxr-resized/2.0.0。需核对它的原始来源、分辨率和处理过程，才能判断与论文的 CXR-JPG 路径是否一致。

## 6. 下一步与教授沟通什么

1. 是否先用富集的 1000 人 pilot 做管线验证，再回到论文的自然模态缺失分布。
2. 当前 partial ETL 还需接入哪些类别，优先处理哪些字典、文本与真实媒体。
3. 时间单位、年龄代理、vitals 窗口和元数据快照怎样登记为实现假设。
4. ECHO 是否开始申请/定位共享副本；四个冻结编码器权重是否已准备。
5. 什么产物算“数据准备完成”：事件计数/来源、真实读取成功率、embedding 缓存、患者窗口与 masks，而不是只有脚本。

这里的原始数据整理不会自动解决模型架构的全部歧义。五模态 pilot、完整六模态复现，以及未来信息审计应分别记录实验范围。
